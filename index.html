Post-mortem: error en un formulario de contacto

Análisis constructivo de un incidente y sus aprendizajes

Resumen ejecutivo

Un formulario de contacto mostraba el mensaje “Enviado correctamente”, pero las consultas no se registraban. El problema fue detectado, investigado y corregido. También se incorporaron controles para evitar que un incidente similar vuelva a ocurrir.

1. Contexto

El incidente ocurrió en el sitio web de un pequeño emprendimiento que utilizaba un formulario para recibir consultas de potenciales clientes. Este canal era importante porque permitía solicitar información sobre productos, precios y disponibilidad.

El objetivo del proyecto era ofrecer una forma rápida y sencilla de comunicación. Sin embargo, durante una revisión se descubrió que el formulario confirmaba el envío sin comprobar si la información había sido registrada correctamente.

2. Problema

Las personas completaban el formulario y veían el mensaje “Enviado correctamente”, pero la consulta no llegaba al sistema.

Impacto

  • Se perdieron posibles consultas de clientes.
  • Las personas recibieron una confirmación incorrecta.
  • El equipo no pudo responder los mensajes.
  • Se afectó la confianza en el canal de contacto.

3. Investigación y causa

Para investigar el incidente se reprodujo el proceso completo: completar el formulario, enviarlo y verificar si la información se almacenaba.

Se identificó que el mensaje de confirmación aparecía automáticamente después de presionar el botón, sin validar el resultado real del envío. Por eso, la página informaba que la operación había sido exitosa incluso cuando se producía un error.

El análisis se realizó sin buscar responsables individuales. La causa estuvo relacionada con la falta de una validación técnica y de una prueba completa del recorrido del usuario antes de publicar el formulario.

4. Acciones realizadas

Acciones correctivas

  • Se corrigió la validación del envío.
  • El mensaje de éxito aparece únicamente cuando la operación finaliza correctamente.
  • Se agregó un mensaje claro para los casos de error.
  • Se realizaron pruebas con datos válidos, inválidos y campos vacíos.

Acciones preventivas

  • Crear una lista de verificación antes de publicar formularios.
  • Probar todo el recorrido desde la perspectiva del usuario.
  • Registrar los errores para facilitar futuras investigaciones.
  • Revisar los cambios mediante commits y Pull Requests.
  • Documentar los incidentes y las soluciones aplicadas.

5. Resultado

Después de implementar la corrección, el formulario fue probado nuevamente. Las consultas comenzaron a registrarse correctamente y el mensaje de confirmación quedó asociado al resultado real del envío.

La solución permitió recuperar la confiabilidad del canal y dejó un proceso de control más claro para futuras publicaciones.

6. Aprendizajes

  • Una confirmación visual no garantiza que una operación se haya completado.
  • Las pruebas deben incluir todo el recorrido realizado por el usuario.
  • Los errores deben analizarse como oportunidades de mejora.
  • La documentación ayuda a evitar que el conocimiento quede en una sola persona.
  • El control de versiones permite registrar y revisar cada cambio.

7. Control de versiones

El proyecto fue documentado en un repositorio público de GitHub. Los cambios se registraron mediante commits para conservar la trazabilidad del proceso.

  • Creación inicial del repositorio y del archivo README.
  • Creación de la estructura inicial del blog.
  • Incorporación del análisis post-mortem.
  • Revisión y mejora del contenido a partir del feedback.

8. Reflexión sobre el feedback radicalmente sincero

Durante la revisión se señaló que la primera versión explicaba el problema con términos poco claros y no mostraba suficientemente el impacto para el usuario.

Recibí esa devolución enfocándome en mejorar el trabajo y no como una crítica personal. Como resultado, simplifiqué el lenguaje, expliqué las consecuencias del incidente y organicé las acciones correctivas y preventivas.

Este proceso me permitió comprender que un feedback sincero, cuando es específico, respetuoso y está acompañado por propuestas de mejora, ayuda a conseguir un resultado más claro y profesional.
